科研工作台教学手册

这门手册把安装启动、页面操作、课题执行、报告产出和常见故障整理成一条可以跟着做的学习路线。它基于 20260828 手册结构、20260917 已批准 PRD/SRS/SDD 和当前目标栈实现，不把未实现能力说成现成功能。

教学页日期：2026-09-17适用：Windows 10/11 + Python 3.12默认地址：http://127.0.0.1:8765/状态：教学呈现，不是正式验收

先看这里：这门手册怎么用

第一次使用

按“准备环境 → 启动服务 → 认识首页 → 创建课题 → 周执行 → 产出报告”的顺序读。不要跳过数据目录和完成门规则。

遇到具体问题

直接进入“常见问题”和对应功能章节。每个操作都要核对页面可见结果、持久化结果和错误提示。

评估功能边界

第 1、12、15、16 章说明哪些能力已实现、哪些仍需 API/CLI、哪些需要人工确认。不要把教学页当作验收证书。

关键红线：不直接修改 SQLite；不在网页填写绝对路径；证据必须位于 data/artifacts/ 相对路径内；Skill 高风险动作必须批准；正式验收要看独立证据，不只看页面。

七步学习路线

  1. 打好基础文档说明、系统组成、数据目录、安装启动（第 1～3 章）。
  2. 认识工作台首页导航、工作包搜索、筛选和详情（第 4～5 章）。
  3. 建立课题创建研究上下文并启动 Workflow（第 6 章）。
  4. 执行和留证周计划、工作项、证据、完成门（第 7 章）。
  5. 生成成果建议、周报、成效卡和 PPTX（第 8 章）。
  6. 扩展与治理Skill、治理、CLI/API（第 9～11 章）。
  7. 核对边界实现状态、故障恢复、运维和验收建议（第 12～16 章）。

1. 文档说明

1.1 编写目的

本文说明科研工作台当前版本的安装、启动、页面导航、常用操作、CLI/API 使用方法、错误处理和功能边界。本文严格以当前源码和测试结果为准，不把 SRS/SDD 中尚未实现的目标描述为现成功能。

1.2 适用范围

适用于 Windows 10/11、Python 3.12 的本地离线部署。系统默认只监听 127.0.0.1，数据保存在项目 data/ 目录，证据文件只能引用 data/artifacts/ 根目录下的相对路径。

2. 系统说明

2.1 系统用途

科研工作台把研究上下文、工作包、周计划、实验记录、证据、完成门和组会材料放到一个本地工作目录中。它记录“做了什么、产生了什么、依据是什么、下一步是什么”，不替代研究人员判断科学结论。

2.2 系统组成

浏览器 -> 本地 Web 服务 -> Application Facade -> SQLite
                                      |-> data/artifacts
                                      |-> Markdown/PPTX/HTML 导出
                                      `-> 受控 Skill 子进程（需批准）

2.3 数据目录

scienceresearch/
├─ data/
│  ├─ scienceresearch.db       # 本地业务数据库
│  └─ artifacts/                # 证据和 Skill 产物根目录
├─ backups/                     # 备份输出
├─ exports/                     # 报告/PPTX 输出
├─ log/                         # demand/engineering 投影日志
├─ doc/                         # 需求、设计和用户手册
├─ output/                      # 报告、QA/截图证据、隔离运行和历史归档
├─ tests/                       # 自动化测试
├─ .codex/                      # 项目 Agent 与 Skill
└─ src/                         # Python 源码

不要直接修改 SQLite 文件，不要在网页中填写绝对路径。data/ 是默认唯一正式业务数据根；测试和截图必须使用 output/ 下的隔离目录。历史手工测试数据库归档在 output/archive/legacy-root-runs/，不能用于替换正式数据库。备份、迁移和正式文档替换前应保留可恢复副本。

3. 安装与启动

3.1 环境要求

  • Windows 10/11 x86-64；
  • Python 3.12 或更高的 3.12.x；
  • 不需要联网，不需要单独安装数据库或 Node.js；
  • 使用 PowerShell 或 Windows Terminal。

3.2 Python 直接启动（推荐）

cd <项目根>
python serve.py

默认地址：http://127.0.0.1:8765/

自定义端口：

python serve.py --port 8770

自定义数据目录：

python serve.py --data-dir <项目根>\data

3.3 PowerShell 启动

cd <项目根>
powershell -ExecutionPolicy Bypass -File .\run_web.ps1

run_web.ps1 只是 Windows 启动包装器，会设置 PYTHONPATH 并调用同一个 Python 服务。启动后窗口没有新提示符是正常现象，表示服务在前台等待请求。

3.4 停止服务

在服务窗口按 Ctrl+C。出现 KeyboardInterrupt 表示用户主动停止前台服务，不代表业务失败。

3.5 端口占用

Get-NetTCPConnection -LocalPort 8765 -State Listen

如果端口被占用，换用空闲端口，例如 8770，并访问对应端口。不要结束不属于科研工作台的 HyperWorks 或其他进程。

4. 首页和导航

启动后进入“科研工作分解与组会汇报”主工作台。页面沿用原型的深蓝侧栏、橙色强调、四项统计卡和目录/详情双栏布局，并显示：

  1. 8 个科研方面、完整 68 个服务端工作包卡片及搜索入口；
  2. 当前 Research Context 数量与周计划数量；
  3. 工作包详情，包括执行方法、可验收交付物、汇报措辞、研究示例，以及进入模板、产物和人工 Skill 的链接；
  4. “本周目标、新增认识、关键证据/产物、当前问题、下周行动”摘要生成器；
  5. 课题、周计划、报告、Skills、治理和运维入口。

启用 JavaScript 时，可直接在首页搜索名称、行动、交付物或汇报措辞，并按八个科研方面筛选。页面实时显示命中数量；无匹配项时显示空态；“清除筛选”会恢复完整 68 个工作包。点击卡片或聚焦卡片后按 Enter，右侧会更新对应的真实详情、当前选中状态和详情入口。

填写摘要字段后，页面会显示本机草稿保存时间；刷新页面可恢复未提交草稿。“生成摘要”会重新生成内容并把键盘焦点移到摘要结果；“清空本机草稿”只删除五个摘要字段和对应 localStorage 项，不影响服务端数据。剪贴板不可用时页面会选中摘要，并提示按 Ctrl+C 手动复制。Workflow、Evidence、Report、工作项和完成状态始终以服务端为准。禁用 JavaScript 时，仍可通过每个卡片的普通链接打开完整详情，并使用服务端搜索表单、标准表单和报告入口。

键盘用户可用页面第一个焦点项“跳到主要内容”绕过导航；系统保持可见焦点。系统检测到“减少动态效果”偏好时，不使用平滑滚动。1000px 以下侧栏变为可横向滚动的顶部导航，600px 以下卡片和摘要字段改为单列；宽表格在自身容器内横向滚动，不使整个页面溢出。

4.4 技术说明板块

入口：首页导航的 “技术说明”，地址为 /technical-docs。该页面内置三份可离线查看的运行期手册：

  1. AI4SCIENCE 教学手册：三阶段、12 个工作流、68 个工作包、成果卡、交接书和证据门；
  2. ScienceResearch 技术栈教学手册：目标栈、请求旅程、迁移兼容栈和质量工具；

操作步骤：

  1. 启动前后端后打开 /technical-docs；

5. 工作包目录

5.1 搜索和筛选

首页快速定位：

  1. 在首页“工作包目录”的搜索框输入名称、行动、交付物或汇报措辞；
  2. 如有需要，选择一个科研方面；
  3. 观察命中数量和仅保留的方面/卡片；
  4. 点击卡片在当前页面查看详情，或点击“打开模板、产物和 Skill”进入完整详情；
  5. 点击“清除筛选”恢复 68 个工作包。

完整目录的服务端搜索：

  1. 点击“工作包目录”，或在首页点击“在完整目录中搜索”；
  2. 输入关键词并选择研究方面；
  3. 点击“筛选”；
  4. 点击结果中的 WP ID 打开详情。

查询结果按稳定 ID 展示方面、工作包名称和交付物。空查询显示全部工作包。

5.2 查看工作包详情

详情页显示：

  • WP 稳定 ID；
  • 所属研究方面；
  • 行动描述；
  • 模板字段；
  • 交付物和完成要求；
  • 使用 Context ID 启动 Workflow 的表单。

当前模板来源是 idea/科研工作分解与每周组会汇报模板_20260828.md。若页面提示 Catalog 无效，先检查模板文件编码和 8 个方面/68 个工作包完整性。

5.3 工作包内新增和查看成效卡

课题工作台的工作包视图中，工作包详情、新增成效卡表单和当前工作包成效卡位于对应工作包卡片下方，不再分离到右侧独立详情栏。

  1. 打开一个课题的 /contexts/{contextId}；
  2. 点击工作包卡片标题、卡片主体或“查看详情”；
  3. 观察 URL 增加 wp=WP-xxx，该卡片显示 aria-current="true" 并展开详情；
  4. 在“新增成效卡”中填写日期、事件、描述，按需勾选重点成效后提交；
  5. 在当前工作包成效卡列表中点击卡片标题展开，执行重点标记、附件上传、下载或预览；
  6. 点击另一个工作包卡片后，URL、选中状态和下方详情同步变化；刷新页面仍恢复同一工作包。

失败行为：日期和事件为空时提交按钮不可用；保存失败、版本冲突、附件超限、类型不允许或同名附件会沿既有错误提示显示，不会静默丢失输入。工作包详情返回入口现在直接回到主目录 /，不再先进入工作包目录。

6. 创建课题与流程

6.1 创建研究上下文

  1. 打开“课题流程”；
  2. 选择类型：project、topic 或 point；
  3. 填写名称、待解决问题和研究目标；
  4. 点击“创建”。

创建成功后，页面返回上下文列表。problem 不能为空。上下文 ID 供后续 Workflow 使用。

6.2 从工作包启动 Workflow

  1. 打开工作包详情；
  2. 将已创建的 Context ID 填入表单；
  3. 点击“为课题启动 Workflow”。

成功后会创建一个状态为 Draft 的流程实例。当前版本不在页面中自动判断科学方案是否正确，研究人员必须自行审阅工作包模板和输入。

7. 周计划和执行台

7.1 创建周记录

  1. 打开“周计划”；
  2. 选择周一日期；
  3. 点击“创建周”。

同一个日期只能创建一条周记录，重复创建返回冲突错误。

7.2 添加工作项

在对应周记录中填写：

  • WP ID：例如 WP-001；
  • 本周工作标题；
  • 交付物；
  • 如果是本周第二项，填写两项工作的关系。

每周最多 2 项工作。第二项必须说明与第一项的关系，超过数量或缺少关系会被拒绝。

7.3 记录执行

  1. 点击“进入执行台”；
  2. 填写动作、输入、结果和产物说明；
  3. 点击“记录执行”。

记录后工作项从 Todo 进入 InProgress。执行记录追加到事件表，不覆盖历史记录。

7.4 登记证据

填写证据名称、类型和相对路径，例如：

result.csv
runs/RUN-xxxx/result.txt

路径必须位于 data/artifacts/ 根目录内。以下路径会被拒绝：

..\\outside.txt
C:\\secret.txt
\\\\server\\share\\file.txt

系统当前登记文件引用，不会替用户判断文件内容是否足以证明科学结论。

target       目标明确

13. 常见问题

13.1 启动后窗口没有输出

正常。服务在前台运行。打开浏览器访问对应地址；停止服务按 Ctrl+C。

13.2 浏览器打开的是 JSON

如果访问的是 /api/contexts、/api/catalog 等 API 地址，显示 JSON 是正常的。用户界面应访问 /、/work-packages、/weeks 等页面地址。

13.3 页面仍是旧版

重启 Python 服务，并在浏览器按 Ctrl+F5。已经运行的 Python 进程不会自动加载源码修改。

13.4 新建第二个周工作项失败

第二项必须填写“第二项关系”；每周最多两个工作项。

13.5 证据路径被拒绝

只填写 data/artifacts/ 根目录内的相对路径，不能填写绝对路径或包含 .. 的逃逸路径。

13.6 完成操作被拒绝

14.1 单一配置文件

所有运行配置保存在启动数据目录下的 operations.json：业务数据根、附件规则、模型 Profile、受 Windows DPAPI 保护的 API Key 密文、版本历史及最近连接测试摘要均以该文件为准。不要手工编辑该文件，也不要把它复制到 release/。业务 SQLite、附件、审计和日志不是配置，不在此文件中。

14.2 业务数据目录

  1. 在“业务数据”区域点击“选择目录”；服务运行在可交互 Windows 桌面会话时，会打开原生目录选择窗口。
  2. 选择目录后检查输入框内容；也可以在窗口不可用时手工输入完整路径。
  3. 点击“保存并在重启后启用”。系统拒绝 release/、output/ 目录。

保存只更新待启用配置，不会自动搬迁既有数据库与附件。重启前当前业务根保持不变；涉及既有业务数据时，先保留可恢复副本并按运维迁移流程确认。

14.3 成效卡附件规则

可设置单文件最大字节数、每张成效卡最大附件数和允许扩展名。保存后仅影响未来上传，既有附件不被改写。版本冲突时刷新页面后重新填写，不要覆盖他人刚保存的配置。

14.4 OpenAI 兼容模型

  1. 填写 HTTPS 服务地址、模型名、超时和 API Key，点击“保存模型配置”。Key 保存后只显示“已配置”，不会再次显示明文。
  2. 查看当前版本、模型、超时和最近测试状态。
  3. 点击“测试连接”。系统仅用已保存 Profile 发起最小 Chat Completions 请求，返回成功、认证失败、限流、超时或协议错误等脱敏状态与耗时。
  4. 连接成功后，输入 Prompt 并生成候选文本；候选不会自动创建或修改课题、工作包、成效卡、附件或研究结论。

测试连接与 Prompt 调用均需要可访问的外部模型服务和有效 Key。保存不会自动测试；测试失败不会覆盖已保存配置。页面、HTTP 响应、审计和日志均不显示 Key、完整 Prompt 或完整模型响应。
