AI4SCIENCE：从模糊想法到可信科研成果

这本手册把 reference/ 中的流程说明、SR Skill 组合方案、Agent 交接说明和工程架构方案，改写为一条可以照着走的学习路径。它解释的不是“AI 能替你做科研”，而是“人如何带着 AI 有证据地做科研”。

适合读者博士生 / 导师 / 科研工程维护者
建议时长入门 20 分钟；全览 60 分钟
学习结果会看懂流程、证据、目录和下一步
权威基线根级 AGENTS.md

1. 它解决什么问题

AI 参与科研后，最常见的失败不是“AI 完全不会写”，而是下面几种混乱：

想法散

聊天记录里有很多灵感，但没有研究问题、边界和证据链。

证据散

论文、代码、实验日志、图和结论分散在不同目录，无法复核。

责任散

同一个 Agent 既做设计、又做评审、还做验收，风险没人独立挑战。

结论过强

一次实验结果被写成普遍规律，缺少反例、边界和人工裁决。

工程不可复现

训练脚本、画图脚本和 Notebook 各自复制流程，结果无法重载。

目录混用

代码、论文、日志和项目管理材料堆在一起，找不到事实来源。

AI4SCIENCE 的答案：用“项目监理 + 科研负责人 + 四个专业 Agent + 人工 Gate + 统一目录”的方式，把科研推进拆成可验证的小闭环。

一句话记忆：AI4SCIENCE 是一个受控的科研流水线。AI 负责加速检索、整理、实现、分析和草稿；人负责方向、真实性、科学解释和最终决定；证据负责判断谁的话有效。

2. 快速开始：新项目第一次启动

假设你只有一个模糊课题，例如“我想做一个更快的科学仿真代理模型”。不要立刻让 AI 写代码，按下面顺序走：

步骤你要做什么预期看到什么常见错误
1. 登记需求先调用项目监理，说明目标、输入、目录、权限和验收方式。需求记录和监督记录。只发一句“帮我做科研”，没有范围和验收。
2. 只读评估让科研项目负责人执行 RPL-01～03，盘点现有证据并判断阶段。成果账本、主阶段、受阻 Gate、一个 P0 / 最多两个 P1。把生成文件数量当成科研进展。
3. 人工选 P0由博士生或导师确认下一步，不自动串行启动昂贵工作。明确批准的唯一工作项。把总体授权扩大成后续所有授权。
4. 工作契约专业 Agent 先返回预算、目标、输入、停止条件和人工检查点。可检查的契约。没有契约就开始联网、写代码或实验。
5. 证据闭环每个关闭的叶子任务一张成果卡；移交时输出交接书。卡片、交接书、原始证据路径。用聊天总结代替证据。
6. 验收与记账负责人执行 RPL-04，项目监理更新日志、质量、变更和成本。验收矩阵和治理记录。把检查通过当成人正式验收。

可以直接复制的提示词

先调用 pr-ps-00-project-supervisor 登记本次只读评估。然后调用 sr-research-project-lead，以当前项目容器为范围，依次执行 RPL-01、RPL-02、RPL-03。只读，不调用其他 Agent，不修改科研材料，不启动实验；所有判断必须引用项目相对证据路径，并给出一个 P0、最多两个 P1。
怎么判断做对了？你能回答：当前证据在哪里、最早未通过的 Gate 是什么、下一步交给谁、完成标准是什么、哪一步必须人批准。

3. 10 分钟核心模型

3.1 三个层次：人机分工不是口号

层次谁负责什么什么时候出现
战略层博士生 / 导师定义目标、审核假设、控制风险、解释统计和机制、决定投稿与公开。关键节点必须介入。
操作层学生或操作者启动 Agent、提供输入、抽查证据、运行实验、修正解释、维护协作。贯穿全程。
执行层专业 Agent / Skill检索、整理、建模、写代码、跑分析、画图、生成审计和草稿。受契约和权限约束。

3.2 六个不可混的概念

工作流

一个阶段内的责任边界，如 PI-E01、MB-X01，共有 12 个。

叶子任务

SR-01～SR-68 中一个具体可关闭的科研工作包。

成果卡

记录一次叶子任务的尝试、发现、证据、产物、结论和边界。

交接书

控制权转移、暂停、阻塞或关闭时的输入输出说明。

Gate

进入下一阶段的人工证据门，不能用后期文件倒推通过。

run 证据

代码、配置、日志、指标、模型、图按同一 run_id 关联。

3.3 数据流：一条证据链

用户需求→监理登记→RPL 只读评估→人工批准 P0→专业工作契约→叶子成果卡→Gate 人工决定→日志 / 质量 / 变更 / 成本

这条链的关键是：对话不是事实来源，文件和可复核证据才是。如果卡片、交接书、原始日志或人工决定缺失，负责人必须报告断链，不能用聊天记忆补造。

4. 角色与权限

4.1 管理与科研调度

角色像什么负责绝不负责
项目监理门卫 + 记账员需求登记、路径检查、质量门、日志、成本、问题反思。不代替科研判断、架构批准或功能验收。
科研项目负责人调度台RPL-01 盘点、RPL-02 阶段诊断、RPL-03 P0/P1 建议、RPL-04 交接验收。不拥有 SR 叶子任务，不自行启动后续昂贵工作。

4.2 四个专业 Agent

Agent适合交给它不要交给它
首席研究员研究问题、范围、价值、证据门、主张强度、路线和归档。文献细读、代码实现、独立评审。
方法构建者文献结构、假设、创新点、模型蓝图、实现契约、方法写作。最终路线决策、实验运行、独立完整性审计。
实验员最小证伪、数据质控、实验矩阵、运行证据、分析、案例和核心图。扩大资源、修改研究问题、替代人工解释。
批判性评审员问题有效性、最近邻差异、反例、完整性、泄漏、误差归因、稿件风险。生产被评审材料，或修改产出方成果。
独立评审原则：谁生产材料，谁就不能同时担任这份材料的批判性评审员。评审必须读取原始证据，并报告误报、漏报和不能得出的结论。

5. 三个阶段与 12 个工作流

Explore 探索

从模糊到精确：定义问题、收集文献、形成假设、挑战反例、设计最小证伪和资源预算。

Execute 执行

从设计到证据：冻结契约、处理数据、复现 baseline、跑实验矩阵、审计完整性、修复阻塞。

Express 表达

从证据到表达：定量分析、机制案例、方法写作、主张收敛、模拟评审、报告和归档。

阶段工作流主责 Agent教学解释关键输出
探索PI-E01首席研究员把模糊想法变成有范围、有价值、有周期的问题。问题定义、边界、P0 计划。
探索MB-E01方法构建者从文献证据到假设、创新点和模型蓝图。证据卡、知识树、假设、架构。
探索CR-E01批判性评审员独立挑战问题、最近邻、机制和反例。差距报告、反例、风险审计。
探索EX-E01实验员设计最小证伪、资源预算和失败回退。实验卡、预算、回退方案。
执行PI-X01首席研究员先执行研究设计冻结 Gate，后续执行结果证据门和路线决策。Gate 决定、资源路线、claim 边界。
执行MB-X01方法构建者冻结 schema、baseline、模块契约、实现计划和接口。可实现契约、接口文档、修复交接。
执行EX-X01实验员建立数据质控和正式实验矩阵，保留完整运行证据。实验日志、指标、产物、run manifest。
执行CR-X01批判性评审员审计完整性、泄漏、误差、归因和最小诊断。完整性报告、原因树、诊断建议。
表达EX-P01实验员定量分析、切片、案例、机制证据和核心图。统计表、案例、Figure brief。
表达MB-P01方法构建者按冻结设计和真实运行记录写可复现方法与实验。方法章、实验章、复现说明。
表达PI-P01首席研究员收敛主张、叙事、修订、报告和归档决定。摘要、故事线、交付决定。
表达CR-P01批判性评审员对草稿执行独立同行评审和意见拆解。审稿报告、修改矩阵。
PI-E01→MB-E01 ⇄ CR-E01→EX-E01→Gate F→MB-X01→EX-X01→CR-X01→结果 Gate→EX-P01 + MB-P01→PI-P01→CR-P01→PI-P01 修订归档

这不是必须一次跑完的流水线。评审否定、实验失败或 Gate 未通过时，要按交接书退回责任工作流，不能跳过前置证据门。

6. 三个阶段门：什么时候不能往前走

Gate必须有什么通过条件典型回退
Explore → Execute：研究设计冻结 Gate FPI-E01、MB-E01、CR-E01、EX-E01 交接。问题、证据、假设、最小证伪、资源边界清楚，并有人工冻结决定。问题不可证伪回问题定义；最近邻不清回文献和差距分析。
Execute → Express：结果证据门MB-X01、EX-X01、CR-X01、PI-X01 证据。运行完成或偏差已解释，完整性审计与主张边界明确，并有人工路线决定。完整性失败回补实验；实现契约漂移回方法构建。
Express 交付 / 归档EX-P01、MB-P01、PI-P01、CR-P01。分析、图表、写作和独立评审可追溯，主张受证据约束，并有人工交付决定。证据不足回实验；叙事过强回 claim 校准。
硬规则：没有具名人工裁决的 accepted 只能按 partial 处理。已有论文草稿、漂亮图表或长报告，不能倒推早期 Gate 已经通过。

始终需要人决定的事项

  • 研究问题、范围、假设、创新点和主张强度。
  • 数据纳入、许可、隐私、伦理和异常剔除。
  • 高成本资源、远程计算、合作承诺、署名和投稿。
  • 提交、发布、专利、开源和对外公开。

7. 68 个工作包地图

SR-01～SR-68 是可关闭的科研叶子任务。学习时不要背编号，先记住八类科研方面和“一个工作包只解决一个未知量”的原则。

01 问题

SR-01～06：场景、形式化、边界、差距、价值、评审。

02 文献

SR-07～14：检索、筛选、深读、树、baseline、增量。

03 假设

SR-15～21：观察、假设、最近邻、反例、优先级。

04 方法

SR-22～29：架构、数学、schema、baseline、预算、回退。

05 实验

SR-30～40：数据、划分、主对比、消融、鲁棒性、完整性。

06 诊断

SR-41～48：定量分析、切片、案例、原因树、结论边界。

07 表达

SR-49～58：主张、故事线、方法实验写作、图、审稿、交付。

08 推进

SR-59～68：验收、拆解、Gate、资源、风险、计划、复盘、归档。

使用原则：当前根级 AGENTS.md 是权威基线。参考文档之间若出现历史编号或归属差异，实际调用时以当前注册表、工作契约和人工批准为准；不要为了“流程完整”一次启动八个方面。

8. 契约、成效卡和交接书

8.1 工作契约：开工前先锁定边界

专业 Agent 在实质工作前必须写清：项目相对根、工作流编号、叶子 Skill、单一目标、范围外事项、cards_read、handoffs_read、输入状态、预期产物、完成标准、人工检查点、停止条件和授权状态。

为什么重要：契约让后续变化可见。如果问题、权限、数据范围或完成标准变化，先改契约，而不是悄悄继续执行。

8.2 成效卡：一个叶子任务一张卡

每张卡必须写 SR ID、Agent、工作流、状态、尝试、发现、证据定位、产物、结论、不能得出的结论、偏差、人工裁决和下一工作流。当前项目命名采用：

YYYYMMDD-成果简称-成果卡.md

接收方先验证卡片、交接和原始证据路径，再建立自己的工作契约。下一步建议不等于授权，尤其是实验、投稿、公开或外部写入。

8.4 证据优先级

  1. 原始数据和不可变运行日志。
  2. 哈希、代码版本、原文和具名人工决定。
  3. 结构化成果卡和交接书。
  4. 阶段报告和聊天总结只能作索引，不能替代证据。

9. 目录与命名：东西应该放在哪里

10. 工程落地：让实验真的可复现

AI4SCIENCE 不是只写文档。参考架构方案的核心是：可导入算法库 + 薄应用入口 + 版本化结果 + 独立运行产物。

10.1 四条架构规则

  1. algorithms 只负责算法，不解析 CLI、不启动 Web、不选择日志目录、不直接画图。
  2. 测试、CLI、HTTP、Notebook 和画图都调用同一个 application/API 用例，不复制训练流程。
  3. 算法返回版本化结构化结果；画图读取结果和指标，不读私有成员，也不要求重新训练。
  4. 日志、指标、模型、检查点和图按 run_id 写到源码树之外。

10.2 目录责任

关注点主目录禁止放入
算法src/<package>/algorithmsCLI 解析、HTTP、画图样式、全局日志初始化。
用例编排application框架请求对象、数据库细节。
入口cli / server算法公式和训练循环。
画图visualization训练副作用、数据下载、算法私有字段访问。
运行输出var/runs/<date>/<run_id>src、tests、仓库根目录。

10.3 一次 run 应该长什么样

var/runs/<date>/<run_id>/
  manifest.json          # 状态、版本、输入摘要、环境、哈希、终态
  config.resolved.yaml   # 合并后的非敏感配置
  logs/events.jsonl      # 结构化事件
  metrics/               # 指标和最终摘要
  artifacts/             # 模型、表格、预测
  checkpoints/           # 可恢复状态
  plots/                 # 可从结果重建的图
失败也要有终态：失败、取消和中断不能只留下“没结果”。至少保留错误类别、已完成产物、配置和日志，才能诊断和回滚。

10.4 测试层级

  • 单元：算法行为、边界、随机性，不联网、不用 GPU、不写用户目录。
  • 契约：所有算法满足 fit/predict、manifest、错误和序列化规则。
  • 集成：真实本地文件、结果重载、指标和画图往返。
  • E2E：已安装 CLI/HTTP、退出码、stdout/stderr、取消和失败。
  • 回归：已确认缺陷和关键数值结果，使用固定数据和明确容差。

11. 一周演练：把流程跑成习惯

以“上周结论是否可靠，本周最该解决哪个未知量”为例：

  1. 周一验收：打开上周承诺、产物和证据，逐项标完成 / 部分 / 取消，记录偏差。
  2. 找未知量：问自己“哪个不确定会让当前路线失效？”把它写成一个可验证问题。
  3. 只选一个 P0：必要时再选最多两个不越 Gate 的 P1。
  4. 先做古法首轮：15～30 分钟人工写初始假设、关键词、边界或手算样例。
  5. AI 辅助：按契约让对应 Agent 做检索、结构化、代码、分析或反例。
  6. 证据门：核对来源、版本、数字、反例、边界和可复现入口。
  7. 人工决定：接受、修改、暂停或转向，并写明理由。
  8. 归档下一步：生成成果卡、交接书、日志、成本和下周计划。
组会表达模板：“本周要回答的问题是……；我读取了……证据；做了……；结果显示……；它支持……但不支持……；剩余风险是……；下周 P0 是……”

12. 常见误区与纠正

误区为什么危险正确做法
“让 AI 全流程自动跑完。”越过后置 Gate、扩大授权，错误会级联。一次只批准一个闭环，检查点暂停。
“生成了很多文件，所以有进展。”文件数量不等于认知更新。看未知量是否减少、Gate 是否通过。
“图很好看，说明结论成立。”图不能替代完整性审计和统计边界。检查数据、泄漏、误差条、反例和 claim-evidence。
“同一 Agent 既写稿又审稿。”失去独立性，容易自我确认。生产者和批判性评审员分离。
“论文写完了，前面设计就算完成。”后期表达不能倒推前置证据。按最早未通过 Gate 回退。
“目录先全部建好。”制造空结构和重复事实源。首个具体产物出现时再创建并登记责任。
“把参考文档中的历史路径照抄。”引入机器路径和过时规则。用项目相对路径，读取当前 AGENTS.md。
“异常点直接删掉。”可能掩盖科学现象或工程缺陷。记录现象、原因树、诊断实验，人工裁决。

13. 收尾清单

  • 用户每项要求都有状态；范围外事项没有被静默实施。
  • 产物路径、命名、责任和生命周期已检查。
  • 每个实际关闭的叶子 SR 有独立成果卡。
  • 控制权转移、暂停、阻塞或关闭有交接书。
  • 关键证据能定位到原文、数据、代码、日志、图表或人工决定。
  • 事实、推测、计划和未执行项分栏记录。
  • 适用边界和不能得出的结论已写明。
  • 提交、推送、发布、删除、远程写入或高成本操作有明确授权。
  • 治理校验器已运行，错误已处理，警告有处置决定。
