# 目标栈一键部署运行脚本 API 说明

## 1. 概述

- 源文件：`scripts/deploy_target_stack.ps1`
- 用途：在项目根目录一键启动、停止、查看状态或清理目标栈。默认使用 Docker Compose；只有显式传入 `-Mode local-isolated` 时才使用本机隔离 PostgreSQL、FastAPI/Uvicorn、Nginx 和已构建 Vue 静态站点。本机依赖同步仍受 `uv.lock` 约束，并可显式选择离线模式；更新源码后可显式强制重启。
- 非目标：不安装或下载任何工具，不访问、导入、覆盖或删除正式数据，不修改部署架构，不做发布、提交、推送或远端 CI 操作，不代表正式验收。
- 运行环境和依赖：Windows PowerShell 5.1+。Docker 模式需要 `docker compose`；本机隔离模式需要调用方提供可用的 PostgreSQL `pg_ctl`、`psql`、`createdb`、`initdb`、Nginx、uv 和 npm。

## 2. 调用方式

以下命令均在 `scienceresearch/project` 目录执行：

```powershell
# 默认 Docker Compose 启动；等价于 -Command up -Mode docker
$env:POSTGRES_PASSWORD = "<至少8位本机密码>"
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1

# 显式本机隔离启动；所有服务仅绑定 127.0.0.1
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1 -Command up -Mode local-isolated

# 查看/停止；local-isolated 未显式 RunId 时选择 state.json 更新时间最新的对应运行
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1 -Command status -Mode local-isolated
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1 -Command down -Mode local-isolated

# 将本机 Nginx 绑定到指定局域网 IPv4；PostgreSQL/FastAPI 仍仅绑定 127.0.0.1
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1 -Command up -Mode local-isolated -DependencySyncMode offline -ForceRestart -WebBindAddress 192.168.173.2

# 弱网/离线环境使用本机 uv 缓存完成锁定依赖同步
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1 -Command up -Mode local-isolated -DependencySyncMode offline

# 源码更新后强制停止当前受管栈并重建；本机会重新执行依赖同步、迁移和前端构建
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1 -Command up -Mode local-isolated -DependencySyncMode offline -ForceRestart

# 只预览本机隔离动作，不创建文件、不启动进程
powershell -ExecutionPolicy Bypass -File scripts/deploy_target_stack.ps1 -Command up -Mode local-isolated -WhatIf
```

`clean` 默认只停止本脚本管理的目标栈并删除本次运行的 PID、日志、生成 Nginx 配置和状态文件；本机 PostgreSQL 隔离数据、artifact 目录和 Docker 卷默认保留。只有同时显式传入 `-RemoveIsolatedData` 才删除该脚本命名 Compose 项目的卷或该 run 目录下的 `postgres-data`、`artifacts`。脚本不会删除正式数据目录。

## 3. 参数

| 参数 | 类型 | 必填 | 默认值 | 约束 | 说明 |
|---|---|---|---|---|---|
| Command | string | 否 | `up` | `up`、`down`、`status`、`clean` | 生命周期命令 |
| Mode | string | 否 | `docker` | `docker`、`local-isolated` | 运行模式；Docker 不可用时不会静默切换本机模式 |
| RunId | string | 否 | 自动日期值 | 字母/数字开头，可含 `.`、`_`、`-`，最长 64 字符 | 运行标识；建议 `down/status/clean` 显式传入 |
| RunRoot | string | 否 | `output/runtime-deploy` | 必须位于项目 `output/runtime-deploy` 内 | 运行证据根目录 |
| WebPort | int | 否 | `8765` | 1024–65535 | Nginx/Web 入口端口，仅绑定 `127.0.0.1` |
| ApiPort | int | 否 | `8877` | 1024–65535 | 本机 FastAPI 端口，仅 Docker Compose 之外的模式直接使用 |
| PostgresPort | int | 否 | `55432` | 1024–65535 | 本机隔离 PostgreSQL 端口，仅绑定 `127.0.0.1` |
| PostgresBinDir | string | 否 | 从 `PATH` 解析 | 目录必须包含 PostgreSQL 工具 | 用于查找 `pg_ctl.exe`、`psql.exe`、`createdb.exe`、`initdb.exe` |
| NginxPath | string | 否 | `nginx.exe` | 可执行文件或 PATH 名称 | 本机隔离 Nginx |
| UvPath | string | 否 | `uv.exe` | 可执行文件或 PATH 名称 | uv 运行 Alembic 和 Uvicorn |
| NpmPath | string | 否 | `npm.cmd` | 可执行文件或 PATH 名称 | npm 构建 Vue |
| RemoveIsolatedData | switch | 否 | 未设置 | 必须与 `clean` 连用才生效 | 显式删除脚本命名 Compose 项目卷或本次 run 的隔离数据；仍不触碰正式数据 |
| DependencySyncMode | string | 否 | `locked` | `locked`、`offline` | 仅本机隔离模式使用；两种模式都执行 `uv sync --locked`，`offline` 追加 `--offline`，不更新锁文件且不联网拉取包 |
| WebBindAddress | string | 否 | `127.0.0.1` | IPv4 | 本机 Nginx 监听地址；设为本机局域网地址时自动保留 `127.0.0.1` 回环监听并开放 Web/API 代理。`0.0.0.0` 监听全部 IPv4 接口。PostgreSQL 和 FastAPI 始终保持 `127.0.0.1` |
| ForceRestart | switch | 否 | 未设置 | 仅影响 `up` | 本机运行中栈先停止受管进程，再执行依赖同步、Alembic、前端构建和启动；Docker 先 `down --remove-orphans` 再 `up --detach --build`。默认省略时保持幂等 `up`：运行中且健康直接返回 |
| WhatIf | switch | 否 | 未设置 | Cmdlet 标准 `-WhatIf` | 输出计划，不执行外部命令、不写文件 |

## 4. 输入、输出与退出码

| 对象/退出码 | 契约 | 示例 | 失败行为 |
|---|---|---|---|
| 标准输入 | Docker `up` 未设置 `POSTGRES_PASSWORD` 时安全提示输入 | 密码长度至少 8 | 空值或过短失败，不打印秘密 |
| `state.json` | 运行模式、状态、URL、本机进程 PID 和时间 | `output/runtime-deploy/local-20260915-120000/state.json` | 损坏时退出 5，提示状态文件相对路径 |
| `runtime-env.json` | 端口、模式和脱敏环境占位 | `postgres_password: <redacted>` | 写入失败由 PowerShell 报错进入退出码 5 |
| 进程日志 | 本机 API stdout/stderr、PostgreSQL、Nginx 访问/错误日志 | `api.stderr.log`、`postgres.log` | 不包含密码或 DSN |
| `health.json` | `/healthz` 与 `/readyz` 均 200 后记录 | `healthz: 200` | 任一超时退出 6 |
| 0 | 命令成功或 WhatIf 预览完成 | `DEPLOY_TARGET_STACK_EXIT` 不输出 | 无 |
| 2 | 参数、路径或状态动作不受支持 | `RunRoot` 越界 | 不写运行目录 |
| 3 | 必需工具缺失或密码无效 | 未找到 `psql` | 不安装、不下载、不降级 |
| 4 | 找不到可操作状态或端口被占用 | `55432` 已被无关进程占用 | 不停止无关进程 |
| 5 | 外部命令失败、状态文件损坏或未处理异常 | Compose/迁移/构建失败 | 保留已产生日志，不伪造成功 |
| 6 | 健康或就绪检查超时 | `/readyz` 未在 180 秒返回 200 | 保留日志和状态供诊断 |

Docker 模式的实际拓扑来自现有 `docker-compose.yml`：PostgreSQL、一次性 Alembic、FastAPI 和 Nginx。脚本使用固定 Compose project 名 `scienceresearch-target`，`up --detach --build` 后通过 Web 入口探测 `/healthz` 和 `/readyz`。`down` 不带 `-v`，不会删除数据库卷。

## 5. 安全、幂等与并发
- 受管进程：本机隔离模式记录启动器和实际监听 PID；停止前校验进程名、命令行、端口和 run 目录，避免 PID 被无关进程复用时误停止；校验通过后按进程树停止。
- 宿主生命周期：脚本启动的是宿主终端/PTY 的后台子进程。普通终端或保持开启的 PTY 中可长期运行；在会话结束即清理后代进程的托管执行器中，必须保持宿主会话开启，否则 state.json 可能遗留 running 而端口已关闭。

- 写入/删除/联网/凭据权限：只写 `output/runtime-deploy/<run-id>`；Docker 模式只操作本脚本命名 Compose project；本机模式只操作 state 中记录的进程和该 run 的 PostgreSQL。密码仅来自环境或掩码提示，不写入日志、仓库或状态。
- 路径边界：`RunRoot` 解析后必须仍在项目 `output/runtime-deploy` 内；`RemoveIsolatedData` 删除前再次校验目标位于所选 run 目录内。
- 正式数据：不访问 SQLite/PostgreSQL 正式数据目录，不读取真实凭据；本机 `initdb` 仅在本次 run 的空目录执行。
- 网络与服务绑定：PostgreSQL 和 FastAPI 始终仅绑定 `127.0.0.1`；Nginx/Web 默认仅绑定 `127.0.0.1`，局域网绑定会同时保留 `127.0.0.1`。开放前应确认网络可信、主机防火墙允许所选端口，并避免在不可信网络使用 `0.0.0.0`；脚本本身不下载工具。Docker build/up 是否访问网络由 Docker 与本地缓存决定，用户执行该模式即表示允许现有 Compose build 流程。
- 重复执行和冲突：Alembic 使用幂等 `upgrade head`；数据库已存在不重复 `createdb`；端口被非本项目进程占用时失败。多个 run 同时使用相同端口会失败，应显式指定不同端口和 RunId。`DependencySyncMode=offline` 不绕过锁文件，仅在 uv 本地缓存可用时同步依赖。
- 中断、恢复和回滚：中断后用同一 `RunId` 执行 `down` 停止记录进程；默认保留隔离数据和日志。删除脚本、测试和文档即可回滚工程入口；Docker `down` 或本机 `down` 停止运行时。
