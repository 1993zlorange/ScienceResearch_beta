# 科研工作分解与每周组会汇报模板

> 适用场景：每周一次课题组组会，本周通常只推进 1～2 项科研工作。  
> 形成依据：Zotero `10-理论基础与综述/14-研究方法与实验设计` 中关于选题、论文检索与阅读、文献树、Idea、探索性实验、实验记录、失败诊断、论文写作、审稿、rebuttal 和学术报告的材料。  
> 核心原则：组会汇报的不是“本周有多忙”，而是“本周新增了什么可靠认识、依据是什么、下一步据此做什么”。

## 1. 科研工作的八个方面

科研工作可以分成八个相互衔接、但可在每周独立汇报的方面：

1. 研究问题与选题；
2. 文献调研与领域结构；
3. Idea、科学假设与创新点；
4. 技术方案与方法设计；
5. 实验设计与执行；
6. 结果分析与问题诊断；
7. 论文与成果表达；
8. 项目推进与下一步计划。

这八方面构成如下闭环：

```text
发现问题 → 建立文献结构 → 提出假设 → 设计方法 → 实验验证
   ↑                                              ↓
形成新问题 ← 论文与交流 ← 提炼结论 ← 分析成败原因
```

每周不必覆盖整个闭环。只需从中选择本周实质推进的 1～2 项，讲清该项工作的输入、行动、证据、结论和下一步。

## 2. 每周组会的固定骨架

无论本周做的是哪类工作，建议首先用一页“本周摘要”回答四个问题：

| 固定内容 | 要回答的问题 | 常用措辞 |
|---|---|---|
| 本周目标 | 本周原计划验证或完成什么？ | “本周聚焦于……，目的是判断/完成……” |
| 新增认识 | 相比上周，确定了什么新事实？ | “本周新增的核心认识是……” |
| 关键证据 | 这个认识由什么支持？ | “这一判断主要由……结果支持，具体表现为……” |
| 下一步 | 根据证据，下一步做什么？ | “因此下周不再继续……，而是优先……” |

推荐的开场表达：

> 本周主要推进了两项工作：第一，完成……，目的是回答……；第二，完成……，目的是验证……。目前得到的主要结论是……。下面重点汇报结论、证据以及仍需讨论的问题。

如果本周只推进一项工作：

> 本周只集中推进了……。虽然工作范围较窄，但已经把……从不确定状态推进到……状态。本次汇报主要说明为什么做、做了什么、得到什么证据，以及下一步如何收敛。

如果尚未得到最终结论：

> 本周尚未形成最终结论，但已经排除了……，并把问题范围从……缩小到……。当前最需要验证的假设是……。

如果实验失败：

> 本周结果没有达到预期，但失败并非无信息。现有证据表明，问题更可能来自……而不是……；我已经设计了……实验用于进一步区分这两个原因。

### 2.1 如何选择本周的1～2个工作包

先判断当前最阻碍研究推进的未知量，再选择能最快产生判别证据的工作包：

| 当前状态 | 本周优先选择 | 不宜立即做 |
|---|---|---|
| 不清楚问题是否值得做 | 场景需求定义、问题形式化、Gap分析 | 直接搭大模型或生成全量数据 |
| 不清楚是否已有类似方法 | 检索式设计、核心文献筛选、最近邻差异分析 | 先写“创新点”或宣称首次提出 |
| 有想法但不知是否成立 | 核心假设、反例构造、最小证伪实验 | 同时实现所有增强模块 |
| 方法逻辑清楚但无法实现 | 接口冻结、算法伪代码、资源预算 | 继续扩展理论叙述 |
| 基线不可信 | 数据划分、baseline复现、可复现实验封装 | 报告新方法优于baseline |
| 结果不好且原因不清楚 | 切片分析、原因树、最小诊断实验 | 无目标地继续调参 |
| 结果较好但论证不完整 | 消融、稳健性、OOD、机制验证 | 直接把单次提升写成普遍结论 |
| 论文结构混乱 | 主张—证据对齐、故事线、核心图表 | 继续堆背景和实验数量 |
| 多任务并行导致延期 | 任务拆解、关键路径、里程碑通过门 | 每条路线都“继续推进” |

一周选择两项时，优先形成下面三类组合之一：

- `输入 → 输出`：文献调研 → Idea；方法设计 → 实验；结果分析 → 论文表达；
- `主证据 → 辅证据`：主对比 → 消融；总体结果 → failure case；精度 → 效率；
- `发现问题 → 关闭问题`：结果异常 → 原因诊断；接口阻塞 → schema冻结；审稿质疑 → 补充实验。

### 2.2 工作包的完成定义

一项工作只有同时满足以下条件，才建议在组会上称为“完成”：

1. 有明确的研究问题或任务目标；
2. 有事先约定的完成标准；
3. 有可检查的交付物，而不是只有口头描述；
4. 有证据支持当前结论；
5. 记录了结论的适用边界和未决问题；
6. 已据此确定下一步行动或停止决策。

如果只完成了动作但没有形成判断，应准确表达为：

> 本周完成了……的执行部分，形成了……交付物；但由于……证据尚未获得，该任务还不能判定为闭环完成。下一步需要……。

## 3. 方面一：研究问题与选题

### 3.1 何时作为本周主汇报内容

- 开始一个新方向或新课题；
- 原有问题过大，需要缩小边界；
- 实验结果迫使研究问题发生变化；
- 需要导师判断选题价值、可行性或优先级。

### 3.2 本周最小交付物

- 一句话研究问题；
- 一张“需求—现状—缺口—目标”图；
- 2～3 个最接近的已有工作；
- 明确的输入、输出、评价指标和问题边界；
- 一个需要组会确认的关键决策。

### 3.3 可执行工作包、交付物与汇报方法

以下工作包可独立作为一周的主任务。每周选择一个即可，不要求同时完成。

| 一周可执行工作 | 具体执行动作 | 可验收交付物 | 汇报要点与常用措辞 | 示例 |
|---|---|---|---|---|
| 场景与需求定义 | 访谈需求方或阅读项目材料；写清使用者、使用时机、输入、输出和性能约束；区分科学问题与工程需求 | 1页场景说明；需求表；输入输出示意图；来源记录 | 要点：谁在什么条件下需要什么。措辞：“该需求来自……，真正需要改进的不是……，而是……” | 对芯片热仿真，明确需求是“多工况温度场快速预测”，不是笼统的“用AI替代仿真” |
| 问题形式化 | 将自然语言问题写成变量、映射、目标函数、约束和评价指标；标注已知量与未知量 | 一句话问题；数学定义；变量表；评价指标表 | 要点：问题能否被计算和验证。措辞：“将问题形式化为……，给定……，预测/反演/优化……” | 给定几何、材料和边界条件，预测全场温度及最大结温，评价场误差、热点误差和推理时间 |
| 研究边界收敛 | 列出可能变化的物理、几何、参数、数据和任务；本阶段固定大部分变量，只保留一个主要矛盾 | 范围内/范围外清单；阶段边界图；删减理由 | 要点：主动不做什么。措辞：“为隔离……的影响，本阶段固定……，只研究……” | 固定求解器和材料模型，只研究变几何条件下的代理泛化，暂不加入数据同化与优化 |
| 现有方案差距分析 | 选择2～3个最近邻方案；用同一组维度比较假设、输入、输出、适用条件和失效情形 | Gap矩阵；最近邻工作对比表；问题缺口陈述 | 要点：差距必须是可验证的。措辞：“现有方法能够……，但依赖……；本研究针对的是……” | 现有神经算子可跨参数，但多数固定网格；缺口是跨几何与跨离散方式的一致预测 |
| 价值与可行性评估 | 分别评估科学价值、工程价值、数据可得性、验证成本和主要风险；给出继续/暂停建议 | 价值—可行性二维表；风险清单；Go/No-Go建议 | 要点：为什么值得现在做。措辞：“价值主要体现在……；能否推进取决于……，最低成本验证是……” | 用20个简化几何先检查输出流形是否低秩，再决定是否生成大规模高保真数据 |
| 研究问题评审 | 把问题陈述交给导师/同学做反例测试；记录“太宽、已有工作、不可验证、价值不足”等质疑并修订 | 问题陈述v2；评审问题清单；修改记录；待决策项 | 要点：问题如何因反馈变清晰。措辞：“根据上次质疑，我将……改为……，目前只剩……需要确认。” | 将“高效可信物理AI”收敛为“具有跨几何误差与校准评价的热场代理模型” |

上述任一工作包的完成标准是：形成一项可以被组会确认或否定的明确判断，而不是只积累背景材料。

### 3.4 各要点及常用措辞

| 汇报要点 | 常用措辞 |
|---|---|
| 研究对象 | “本研究关注的对象是……，具体场景为……，暂不覆盖……” |
| 实际需求 | “在……场景下，现有流程需要……，主要代价/风险是……” |
| 核心问题 | “我希望回答的核心问题是：在……条件下，能否通过……实现……” |
| 现有不足 | “目前主流方法在……条件下表现较好，但当……时会出现……” |
| 问题边界 | “本阶段固定……，只研究……的影响，以避免同时引入……” |
| 研究价值 | “如果该问题得到解决，理论上可以说明……，工程上可以支持……” |
| 可验证性 | “该问题可以通过……数据和……指标验证，不依赖无法获得的……” |
| 风险判断 | “当前最大风险不是实现难度，而是……是否成立；我计划用……快速判断。” |
| 请求决策 | “希望组会重点判断：这个问题是否足够独立，以及……是否应纳入当前范围。” |

### 3.5 一项选题工作的完整汇报示例

> 本周集中收敛研究问题。原问题同时包含变几何代理、数据同化和鲁棒优化，范围过大。本周将第一阶段问题限定为“在固定物理模型、变化几何和边界条件下，如何学习可泛化的高维场预测模型”。现有方法主要不足是几何表示与物理边界信息没有显式对应。该问题可通过跨几何测试误差、物理残差和关键 QoI 误差共同验证。当前希望组会确认：第一阶段是否只保留代理预测，暂缓数据同化与优化闭环。

## 4. 方面二：文献调研与领域结构

### 4.1 何时作为本周主汇报内容

- 新进入一个领域；
- 需要确认 Idea 是否已有类似工作；
- 需要选择 baseline、数据集或评价指标；
- 投稿前需要重新定位创新性；
- 文献之间关系混乱，需要建立 literature tree。

### 4.2 本周最小交付物

- 检索范围、关键词和筛选标准；
- 不是文献清单，而是一张方法谱系或问题树；
- 3～5 篇最关键文献的可比较表；
- 已知挑战、已有 insight 和尚未解决问题；
- 对研究方案产生的具体影响。

### 4.3 可执行工作包、交付物与汇报方法

| 一周可执行工作 | 具体执行动作 | 可验收交付物 | 汇报要点与常用措辞 | 示例 |
|---|---|---|---|---|
| 检索式设计与试检索 | 将问题拆成对象、任务、方法和约束四组词；构造布尔检索式；试检索并修正噪声词 | 检索式；数据库与时间范围；命中数；纳排标准 | 要点：检索是否可复现。措辞：“本周检索的目标是回答……，覆盖……，明确排除……” | 检索 geometry generalization + surrogate/neural operator + mesh/point cloud，排除仅固定几何工作 |
| 核心文献筛选 | 先看标题摘要，再看方法与实验；按直接相关性、证据强度、可复用性评分 | PRISMA式筛选台账；核心文献10～20篇；排除理由 | 要点：为什么这些文献关键。措辞：“从……篇候选中保留……篇，主要依据是……” | 从120篇中筛出18篇跨几何场预测论文，其中6篇提供公开代码和跨几何测试 |
| 单篇深读与证据卡片 | 逐项提取研究问题、假设、方法、数据、指标、结果、局限和可复用资产；核对正文而非只看摘要 | 3～5张文献证据卡；原文页码/图表定位；复现线索 | 要点：论文真正证明了什么。措辞：“该文声称……，但直接证据只支持……，其适用范围是……” | 某方法声称跨几何泛化，但测试几何与训练集同属参数化翼型，因此不等于跨类别泛化 |
| 方法谱系/Literature tree | 确定分类轴；将核心文献放入树中；标出继承、替代和组合关系 | 方法树；时间线；每个分支代表工作与优缺点 | 要点：领域结构而非论文列表。措辞：“按……这一关键差异，现有方法分为……” | 将几何代理分为规则网格、图网格、点云和隐式场表示四条路线 |
| Novelty tree | 把已有创新拆成问题设定、表示、模型、训练、评价和应用层；标出拥挤区与空白区 | 创新点矩阵；最近邻差异表；候选创新位置 | 要点：创新位置是否真实。措辞：“已有创新集中在……，真正较少覆盖的是……” | 网络结构创新密集，但几何分布外评价、局部热点可信度和失效检测研究不足 |
| Challenge-insight tree | 为每个挑战收集原因解释、解决 insight、支持证据和剩余缺口 | 挑战—原因—洞见—方法—证据树；待验证问题 | 要点：从挑战导向方案。措辞：“挑战……的根因可能是……，已有工作提供的有效 insight 是……” | 变网格泛化困难源于离散依赖；现有洞见包括坐标算子、连续核和层次网格表示 |
| Baseline与基准调研 | 汇总公开代码、许可证、数据、指标、算力和复现难度；确定最低、主流和强baseline | Baseline选择表；代码链接；预期资源；公平比较清单 | 要点：选择理由和可比性。措辞：“选择……不是因为易实现，而是它代表……路线。” | 选择POD-MLP作低成本基线、GNO作图方法基线、Transolver作强模型基线 |
| 周度文献增量更新 | 对上周以来新增文献做去重、分类和影响判断；只汇报改变当前认识的文献 | 新增文献清单；结构变化；对方案/实验的影响记录 | 要点：新增认识而非阅读数量。措辞：“本周新增……篇，但只有……篇改变了当前判断，具体是……” | 新发现的导数知情降维工作使输入降维实验必须加入active subspace对比 |

### 4.4 各要点及常用措辞

| 汇报要点 | 常用措辞 |
|---|---|
| 调研目标 | “本周调研不是全面综述，而是为了回答……是否已有解决方案。” |
| 检索范围 | “检索覆盖……数据库、……年至今，关键词包括……，排除了……” |
| 方法分类 | “现有工作可以按……分为三类，而不是按论文逐篇罗列。” |
| 代表工作 | “这一分支最有代表性的工作是……，它解决了……，但依赖……” |
| 横向比较 | “三类方法的主要差异在输入表示、监督信号和泛化边界，而不只是网络结构。” |
| Novelty tree | “已有创新主要集中在……，而……这一层仍缺少系统研究。” |
| Challenge-insight tree | “针对挑战……，已有 insight 是……；但在……条件下仍未验证。” |
| 文献可信度 | “目前这一结论由……篇直接证据支持，其余文献只提供间接参考。” |
| 对本项目影响 | “调研后，我保留……，放弃……，并新增……作为必须比较的 baseline。” |
| 未完成项 | “目前缺口是……分支尚未覆盖，因此关于……的判断仍是暂定结论。” |

### 4.5 只完成文献调研时的完整汇报示例

> 本周只完成了几何泛化代理模型的定向调研，目标是判断几何编码是否必须显式包含网格拓扑。现有方法可分为点云编码、图/网格编码和隐式坐标表示三类。图/网格方法在保留连接关系方面更强，但跨网格迁移成本较高；隐式表示更灵活，但对复杂边界和材料分区的表达证据不足。由此得到的新增认识是：当前方案不能只比较网络精度，还必须加入跨离散方式测试。下周计划选取每类一个代表 baseline，统一数据划分和评价指标。

## 5. 方面三：Idea、科学假设与创新点

### 5.1 何时作为本周主汇报内容

- 从文献缺口形成了新想法；
- 需要判断 Idea 是否值得投入实验；
- 方法有效但尚不清楚真正创新在哪里；
- 多个候选 Idea 需要排序。

### 5.2 本周最小交付物

- 一句话 Idea；
- 可证伪的核心假设；
- 与最接近工作的差异表；
- Idea 拆分后的探索点和技术挑战；
- 一个最低成本的证伪实验。

### 5.3 可执行工作包、交付物与汇报方法

### 5.5 一项Idea工作的完整汇报示例

> 本周形成的核心Idea是：利用输出对输入参数的导数信息识别有效低维方向，再在该方向上训练代理模型。它不是对输入做无监督压缩，而是让降维方向直接服务于目标场预测。核心假设是，多参数输入虽然维数较高，但输出敏感方向具有低秩结构。最低成本验证是先对已有样本计算 Jacobian 谱，并比较导数知情方向、PCA方向和随机方向下的预测误差。如果谱没有明显衰减，该Idea就不适合当前数据。

### 8.5 实验失败时的完整汇报示例

> 本周新模块没有提升总体测试误差，但失败样本并非随机，主要集中在小尺度热点区域。当前有三个候选原因：网格分辨率不足、损失函数低估局部区域、编码器缺少材料界面信息。通过提高模型容量，结果没有改善，因此暂时不支持“容量不足”。下一步将分别增加热点加权损失和界面编码，用两个最小实验区分后两种原因。现阶段只能得出“当前实现无效”，不能否定整体Idea。

### 8.6 结果为正时应避免的过度结论

不要说：

> 模型证明了该方法具有很强的泛化能力。

建议说：

> 在当前数据划分、参数范围和三个随机种子下，该方法的测试误差稳定下降。它支持“……机制在当前设置中有效”，但跨几何类别和分布外条件仍需单独验证。

| 进度判断 | “当前处于……阶段，距离……里程碑还缺……” |
| Blocker | “目前阻塞不是一般性‘还需优化’，而是……接口/数据/决策尚未确定。” |
| 依赖关系 | “任务B依赖任务A的……输出，因此本周不应并行启动……” |
| 需要协助 | “需要老师/同学协助确认……，期望得到的不是泛泛建议，而是……决策。” |
| 下周任务 | “下周任务一是……，交付物为……，完成标准是……” |
| 风险 | “若到……仍出现……，则触发备选方案……” |
| 优先级 | “根据当前证据，优先级从……调整为……，暂停……” |
| 里程碑 | “下个里程碑不是‘继续实验’，而是形成可支持……结论的完整证据包。” |

### 10.5 一项项目推进工作的完整汇报示例

> 上周计划完成多物理数据统一接口和两个baseline，本周接口与MLP baseline已经完成，图网络baseline因网格连接信息缺失未完成。当前阻塞点是数据导出格式，而不是模型训练。下周第一项任务是补齐连接关系和边界标签，交付物为冻结的数据schema及10个通过校验的样本；第二项任务是跑通图网络baseline，完成标准是训练、验证和测试日志可复现。若周三前数据仍无法导出，则先使用公开网格数据验证模型链路。

## 11. 每周只完成一项工作时怎么汇报

只完成一项工作并不意味着内容不足。建议用“纵向讲透”代替“横向凑数”，结构如下：

1. 上周留下的具体问题；
2. 本周为什么只聚焦这一项；
3. 本周采取的行动；
4. 获得的证据或产物；
5. 新增认识；
6. 仍未解决的问题；
7. 下一步最小行动；
8. 需要组会做出的决策。

通用模板：

> 上周的关键问题是……。由于它决定后续是否继续……，本周只聚焦这一项。我完成了……，并用……进行检查。结果表明……，因此我们现在可以确定……，但还不能确定……。下一步将通过……验证。希望组会帮助判断……。

建议控制在 6～8 页：

1. 本周结论；
2. 问题与目标；
3. 方法或行动；
4. 关键证据；
5. 分析与结论边界；
6. 下一步与待讨论问题。

## 12. 每周完成两项工作时怎么汇报

两项工作应先说明它们的关系，避免像两份日报拼接。

### 12.1 两项工作前后依赖

例如“文献调研 → Idea形成”“方法设计 → 实验验证”：

> 本周两项工作存在前后关系。首先通过……确认……，在此基础上设计/验证了……。第一项工作的结论决定了第二项工作的选择。

### 12.2 两项工作并列支撑同一问题

例如“理论分析 + 实验分析”“总体误差 + failure case”：

> 本周从两个互补角度回答同一问题：工作一分析……，工作二验证……。两者共同支持/尚未共同支持……结论。

### 12.3 两项工作属于不同项目

> 本周推进两个独立任务。项目A已进入……阶段，重点结论是……；项目B仍处于……阶段，本周只汇报……。为避免混淆，两部分分别给出结论和下一步。

建议控制在 8～12 页：

1. 本周两项工作的关系和总结果；
2. 工作一：问题、行动、证据、结论；
3. 工作二：问题、行动、证据、结论；
4. 两项工作对总体研究问题的共同影响；
5. 下周优先级和待讨论问题。

## 13. 常见周进展情形的措辞

### 13.1 本周主要在复现 baseline

> 本周目标是建立可信比较基准，而不是追求新方法结果。已经对齐了数据划分、评价指标和训练预算。当前复现结果与原文相差……，差异可能来自……。在差异未解释前，不进入新方法比较。

### 13.2 本周主要在生成或清洗数据

> 本周完成的是后续实验的证据基础。新增/清洗了……个样本，修复了……问题，并通过……检查数据一致性。当前仍有……比例的异常样本。只有在……校验通过后才冻结数据版本。

### 13.3 本周主要写代码或搭建平台

> 本周代码工作的研究目的，是消除……对实验结论的干扰。完成了……模块和……接口，已经用……测试验证。该工作本身不构成科学结论，但使下周的……实验具备可复现条件。

### 13.4 实验仍在运行

> 完整实验仍在运行，本周不提前解读不完整结果。已经完成的部分是实验设计、配置冻结和baseline检查。目前预计……完成；若资源占用超过……，将缩小到……进行机制验证。

### 13.5 本周没有得到性能提升

> 本周没有得到性能提升，但已确认……不是有效改进方向，并排除了……原因。这个结果减少了后续搜索空间。下一步只保留……假设，不再继续盲目调参。

### 13.6 本周主要阅读和学习基础知识

> 本周学习……不是一般性知识积累，而是为解决……中的具体障碍。已经明确……定义/推导，并发现当前实现中的……与理论条件不一致。下周将把这一认识落实为……修改或实验。

### 13.7 本周进展低于计划

> 本周原计划……，实际只完成……。主要原因是此前低估了……，而不是简单的时间不足。当前已把剩余工作拆成……。为了不继续延期，下周将暂停……，优先关闭……。

### 13.8 需要导师或组员帮助

避免只说“请老师指导”。建议明确决策问题：

> 目前我在A和B两条路线间需要做选择。A的优势是……、风险是……；B的优势是……、风险是……。基于现有证据我倾向A，希望组会重点判断……。

## 14. 每页幻灯片的表达规范

### 14.1 标题写结论，不写主题

不建议：

> 实验结果

建议：

> 边界编码将跨边界条件误差降低 18%，但对分布外几何无改善

不建议：

> 文献调研

建议：

> 现有几何代理分为三条路线，跨离散泛化仍缺少统一验证

### 14.2 一页只承担一个论证任务

每页应能回答：

- 这一页希望听众相信什么？
- 用什么证据支持？
- 证据的适用范围是什么？
- 该结论对下一步有什么影响？

通用讲解句式：

> 这一页主要说明……。左图/表展示……，右图/表展示……。最关键的观察是……。因此目前可以判断……，但该结论仅适用于……。

### 14.3 图表汇报措辞

- “横轴表示……，纵轴表示……，颜色/线型区分……”；
- “这里关注绝对值/变化趋势，而不是单个最优点”；
- “相比baseline，提升主要来自……区间”；
- “误差条表示……，不同种子间波动为……”；
- “该差异是否具有稳定性，需要结合……判断”；
- “这个异常点对应……样本，初步原因是……”；
- “图中没有展示……，因此不能据此说明……”。

## 15. 组会汇报的结论强度

汇报措辞应与证据强度一致：

| 证据状态 | 推荐措辞 |
|---|---|
| 单次现象 | “观察到……” |
| 多次稳定出现 | “结果稳定表明……” |
| 支持某个机制 | “结果支持……假设” |
| 排除部分原因 | “现有证据基本排除……” |
| 证据不足 | “目前尚不能判断……” |
| 与预期冲突 | “结果不支持原假设，需要重新检查……” |
| 适用范围有限 | “该结论目前仅适用于……” |

尽量少用“证明了”“完全解决”“显著优于所有方法”“具有很强泛化性”。除非证据覆盖了必要的统计检验、对比范围和泛化条件。

## 17. 汇报前检查清单

### 内容检查

- 是否在第一页给出本周最重要的结论；
- 是否只选择了本周实际推进的 1～2 个方面；
- 每项工作是否说明了问题、行动、证据、结论和下一步；
- 是否区分“事实、分析、猜测和计划”；
- 是否说明当前结论的适用范围；
- 失败实验是否转化为原因假设和诊断实验；
- 下周计划是否有可检查的交付物和完成标准；
- 是否提出了明确、可回答的讨论问题。

### 图表和证据检查

- 图表是否标注数据、单位、样本数和误差定义；
- baseline 是否使用相同数据划分和预算；
- 是否报告随机种子、置信区间或波动范围；
- 是否保存代码版本、配置、日志和原始结果；
- 是否展示具有解释价值的 failure cases；
- 是否避免从单次实验推导过强结论。

### 表达检查

- 幻灯片标题是否直接写结论；
- 是否删除与本周进展无关的重复背景；
- 是否避免逐篇念文献、逐行讲代码和逐表报数字；
- 是否把最需要讨论的问题留出足够时间；
- 最后一页是否明确说明下周做什么以及为什么。

## 18. 最终建议

周组会最有价值的单位不是“完成一个大阶段”，而是完成一次可追踪的认知更新。即使一周只完成一项工作，只要能够说明：

1. 原来不知道什么；
2. 本周用什么行动获得证据；
3. 现在知道了什么；
4. 还有什么不能确定；
5. 下一步用什么最小行动继续判断；

这次组会就是完整且有效的科研汇报。
